### Topic 1: AI

#### 1. How people use AI for shopping

**Role in the journey**
- AI chat and traditional search are used interchangeably within the same stage;
- AI complements rather than replaces search. 
- 42% of requests are exploratory (attraction/destination-type). *(Shopping with a Platform AI Assistant)*

**It shifts online behavior**
- ~20 weeks after adopting an LLM, a user's **traditional search drops 20%**+ vs before adoption.
- High-traffic sites hold up; **smaller sites show signs of significant traffic loss**.
- Display-ad impressions fall, especially among heavy online shoppers.
- *Padilla, Lam, Lambrecht & Hollenbeck (2025/26). Comscore clickstream, 1M+ users, 2022–2023.*

**Recommendation moves consumers (open web)**
- When AI **recommends a brand to someone not previously exposed**, within 7 days: brand search +4.3pp, brand-site visits +2.4, retailer-page visits +1.0. Most of this path is invisible to last-click attribution.
- Method: opt-in users get one identity tag; their AI-chat and browsing timelines are matched at the individual level (e.g. "Garmin" recommended in ChatGPT at 2:00pm, Google search for "Garmin" at 2:05pm).
- *Iannelli & Ai (2026). User-authorized clickstream stitched to the same user's ChatGPT/Claude/Gemini chats.*

**Adoption size**
- Europe — McKinsey (2 Mar 2026; FR/DE/UK): 63% compare brands/models/prices/reviews, 55% learn a category, 46% seek inspiration; 56% accept suggestions but decide themselves; 47% won't let AI auto-manage repurchases.
- US — McKinsey × ICSC (Apr 2026; 3,004 consumers + exec interviews): 68% used ≥1 AI tool in the past 3 months; agentic commerce up to ~$1T by 2030.
- Global — BCG (2025/26; Consumer Radar survey + AI-assisted interviews): shopping is the 3rd-largest GenAI use, +35% shopping use (Feb–Nov 2025); 60%+ highly trust GenAI output; India 64% use it during purchase.

**Trust**
- Not blind; it builds through a dynamic "trust calibration" process.

**How they ask** (query patterns, not shopping-specific)
- AI Mode queries ~3x longer than traditional search; follow-ups +40%/month. Openers skew what / how / I / is / can ("I" = treats it as conversation); "which" queries resolve ~40% faster (mostly "which of" / "which one"); "where should I" and "ideas for" are rising.
- [Amazon Rufus](https://www.aboutamazon.com/news/retail/how-to-use-amazon-rufus): four question types — single item (easy to clean? clean beauty?), comparison (gas vs. wood-fired oven?), own orders (when did I last buy sunscreen?), scenario-driven (what do I need for a summer party?).
- [OpenAI shopping](https://openai.com/index/chatgpt-shopping-research/): simple (price, one feature) vs deep (comparisons, multiple constraints, trade-offs); deep queries cluster in parameter-rich categories (electronics, beauty, home & garden, kitchen, sports/outdoors).

#### 2. Algorithm side: independent answers + region

**Independence — separate four layers**
- Context (explicit conversation history) · Account/product (memory, personalization, geo & language signals) · Service (caching, batching, silent model updates) · Statistical (can repeated samples of one prompt be treated as i.i.d.?).
- True carry-over (one query affecting the next) lives almost only in the first two layers. Service-layer issues are time-correlated noise and drift; they don't leak content forward.

**Design principles**
- Stateless API call = the unit: one trial, one fresh request, full prompt. Never run multiple trials in the same thread (multi-turn context shifts behavior; Laban et al.: ~39% drop vs single-turn). E.g. Responses API with `store=false`; the API ignores ChatGPT Memory and chat history.
- `temperature=0` + fixed seed ≠ determinism. Treat output as a sample from a distribution: repeat-sample each prompt and report stability metrics.
- Log model snapshot, date, `system_fingerprint`, and all parameters; a same-named service drifts over short periods (Chen, Zaharia & Zou 2024).
- Consumer UI (ChatGPT web/app) vs API are two different experimental subjects (system prompt, moderation, memory, search, geo all differ). To study what real consumers see, use sock-puppet (controlled accounts) or logged-out designs, controlling IP and language.
- Cluster by prompt/item: N repeats of one prompt ≠ N independent obs. Use cluster-robust SEs and paired differencing (Miller 2024), same logic as `reghdfe ..., cluster()`.
- Per prompt × condition, repeat N times; report agreement rates TARr@N (raw) and TARa@N (parsed) (Atil et al.) plus variance and CIs.
- Choosing N: Żatuchin (2026, preprint) D-study for brand-rec audits — reliability ~0.58 at 5 reps, ~0.81 at 15.
- Randomize trial order and interleave conditions in one time window (not "A in the morning, B in the afternoon"); for long collection, block by time and add time fixed effects.
- Use several semantically equivalent wordings/formats and report a range, not one prompt's result (Sclar et al., ICLR 2024).

**Region / geography**
- Model-level studies (API / open weights) almost all inject geography via the prompt (country persona, "assume you are from country X", target-language questions), because API calls carry no end-user location.
- Audits of consumer products (ChatGPT web, Copilot, Gemini) use residential proxies / VPN / fixed institutional IPs plus browser language settings.
- Declaring a country in the prompt pulls output local, but brings stereotyping.
- Web UI vs API diverge sharply (recommendation sources can barely overlap), so API-only findings don't extrapolate to real users.
- AI Forensics / AlgorithmWatch (2023, grey): audited Bing Chat on Swiss federal and German state elections via VPN + Swiss/German residential IPs, grouped by language (DE/FR/EN); early use of IP location as a design variable.
- Kamruzzaman et al. (2024): "country-of-origin effect" — stating the user's country makes the model prefer that country's local brands; direction can reverse.
- OpenAI web-search and Perplexity Sonar API both support a `user_location` parameter (country, city).

> | H5 | Memory-induced sycophancy | User profile makes the model more likely to agree | Jain et al. 2025 (MIT) | Zero-context baseline control |
> | H6 | Exit IP / query language | Determines which market's products are recommended | arXiv 2608.30052 (2026, logged-out ChatGPT vs API) | Fix and manipulate as a factor |
